Prism as a validation proxy API Server

NodeJS
API
Proxy

Network - Pixabay

Pablo Urrea

5 minutes reading
Published
25/05/2024

Use Prism as a proxy for REST APIs, a tool that not only validates requests according to OpenAPI definitions but also facilitates redirecting them to a single port, thereby improving the workflow and robustness of applications.

In the article Prism As A REST API Testing Server I delve into the installation and basic configuration of Prism, so in this article, I will skip the installation and validation process that Prism uses with OpenAPI definitions.

 

Using Prism as a REST API proxy has the main advantage of validating requests against the port, but it is also important to note that this functionality redirects all requests to a single REST API port, which can be challenging if you have more than one port in your functionality. This concept is easier to understand with the following diagrams:

 

 

 

 

Intercepting requests with Prism's network. With this clear, setting up the proxy is as simple as running the following command:

prism proxy openapi.yaml https://www.example.com/api/v1/port/

 

Although Prism allows configuring some proxy settings via parameters, below are the most useful ones:
--errors: Recommended parameter. The response to the request generates an error if it does not validate with the definitions. For example:

prism proxy openapi.yaml https://www.example.com/api/v1/port/ --errors

-h: Changes the IP address to the one provided. For example:

prism proxy -h 0.0.0.0 openapi.yaml https://www.example.com/api/v1/port/

-p: Changes the network port to the one provided. For example:

prism proxy -p 9999 openapi.yaml https://www.example.com/api/v1/port/

-m: Enables multiprocessing. Recommended parameter if the proxy is going to receive many requests. For example:

prism proxy -m openapi.yaml https://www.example.com/api/v1/port/

 

Once the server is started, you can make requests to the service from your machine to the local IP (or to the IP of the remote machine if installed on a remote server):

curl http://localhost:4010/users

Prism accepts configurations for GET, POST, PUT, PATCH, and DELETE methods.

 

 

What happens at the real REST API port? Debugging the request at the real REST API port, you can verify that the proxy has made the request against the port, sending the query parameter “q” with the URL of the port to interact with. For example, if you have a REST API port /users/delete that performs an action with the DELETE method on a user ID in the body {id: 1}, when making the request against the Prism proxy, it validates the request and forwards it to the real REST API port /api/v1/port as /api/v1/port?q=/users/delete with the DELETE method and the request body {id: 1}. The port returns a status code and a message in the body that is transferred to the proxy, and then the proxy returns to the client:

 

 

 

Conclusion. Prism emerges as a valuable tool for validating and redirecting REST API requests, functioning as an effective proxy that ensures requests comply with OpenAPI definitions before being processed by the real REST API port. This not only simplifies the workflow by intercepting and validating requests but also enhances the robustness of applications through strict adherence to the REST API specifications, resulting in a more secure and efficient development process.


 

If you need more information about the package, you can check Prism's documentation.
