Optimization and automatic compilation of web styles with SASS

NodeJS
SASS
CSS

SASS logo

Pablo Urrea

10 minutes reading
Published
30/06/2024

SASS (Syntactically Awesome Style Sheets) or Super CSS for friends (SIUUUUUUUSS in Portuguese), allows for automatic compilation of component-based styles for web theme creation. This system is quite useful for unifying the CSS file of a web page to reduce file transfer and improve performance (One step closer to getting a 100/100 score from Google Lighthouse).

 

Quick, easy, and for the whole family. The first thing to do is to install Node, the main executor of SASS. It's best to follow the steps on the official Node page for the environment you need: https://nodejs.org/en/download/package-manager.

Now that Node is working correctly on your machine (or should be), it's time to install SASS. You can install it globally on the whole machine (recommended for testing) as recommended in the official SASS documentation:

npm install -g sass

Or you can install SASS in the project where you will use the package from the root folder of the package (don't forget to run the Node project initiation command npm init first):

npm install sass

 

Execution time is shorter than expected. Compiling the file is quite simple; the sass command accepts various parameters, but the most useful ones (probably) are the input path SCSS, the output path CSS, the style parameter for compiling expanded or compressed styles (expanded (default) or compressed), and the watch parameter to automatically compile whenever it detects a saved change in the SCSS files. An example of how the command looks with these parameters applied is:

npx sass --watch --style=compressed path/to/file.scss:path/to/file.css

In this example, SASS is instructed to compile the main SCSS file in a compressed format (the one that usually contains all the dependencies) and to compile the compressed result into the CSS file at the specified path. If you need more configurations, here is the output of sass --help:

In a real example, let's consider the following unoptimized CSS file without SASS:

body {
  font: Helvetica, sans-serif;
  color: #333;
}

This file takes up 54 bytes, and if more styles with the same color or font need to be added, a copy of the same style would be required, which is cumbersome for the developer.

Now, I convert this CSS file to SCSS:

$font-stack: Helvetica, sans-serif;
$primary-color: #333;
body {
 font: $font-stack;
 color: $primary-color;
}

And upon compiling it with compression, this is the result:

body{font:Helvetica,sans-serif;color:#333}

It takes up 43 bytes, and the developer does not need to bother decompressing it to edit it, as the styles are configured from the SCSS file.

 

In the previous examples, the size difference may not seem significant, but when scaled to larger projects, the difference becomes considerable, and the convenience of using variables becomes more necessary.

Another example of the advantages of SASS is element nesting. Multiple child elements can be nested under the same parent umbrella. The following CSS file has many nestings that, during development, can be confusing and lead to errors, causing styles to not function correctly because the element to be selected is not properly recognized:

body element.class__one#id-element .class__one__two {
 font: $font-stack;
 color: $primary-color;
}

When converted to SASS, it is evident that the nestings improve the readability of the styles:

$font-stack: Helvetica, sans-serif;
$primary-color: #333;
body {
  element {
    &.class {
      &__one {
        &#id-element {
          .class {
            &__two {
              font: $font-stack;
              color: $primary-color;
            }
          }
        }
      }
    }
  }
}

 

 

Conclusion. These examples are just the tip of the iceberg that makes SASS improve style development. It is best to read the official SASS documentation to see all the tool's possibilities. They also have an online compiler so you can test the CSS code before migrating your project.
