Ultimate Cron to master all automated tasks in Drupal

Drupal
Cron

Representation of Drupal's cron task manager as Salvador Dalí's “The Persistence of Memory”

Pablo Urrea

12 minutes reading
Published
27/08/2024

The Drupal core includes its own integrated cron that allows you to schedule automated tasks, which provides the ability to add custom tasks that will run when cron is triggered in Drupal. The issue is that Drupal executes all tasks during cron execution, which can be inconvenient if you need one of them to run more or less frequently.

This poses the dilemma of whether to run cron tasks less frequently, thus having a smaller impact on the server and leaving behind tasks that need to be run more often; or, on the other hand, to run tasks more frequently, thus overloading the server with less necessary tasks.

It is also possible that a daily task that requires significant execution time, higher server power, or the server's full bandwidth should run during periods of low user activity (e.g., at night, unless it's a programming forum server 🌚).

 

 

The ultimate cron. To address this issue, there is a contributed project in Drupal called Ultimate Cron, which allows you to configure and schedule cron tasks individually. To install it, do so like any other module in Drupal with Composer by running the following command in the console:

composer require drupal/ultimate_cron

And enable it from the “Extend” administration section or via Drush in the console with the command:

drush en ultimate_cron

After enabling it, all cron tasks will appear at /admin/config/system/cron/jobs or Administration > Configuration > System > Cron > Cron Jobs:

 

You can now sort tasks, edit them, disable them, or view the reports they generate during execution. When editing a task from “Operations,” you can configure the scheduler to be Simple (Executes the task every 1 minute, 5 minutes, 15 minutes, 30 minutes, 1 hour, 3 hours, 6 hours, 12 hours, once a day, or once a week) or to be of type Crontab, which is a way to configure natural time periods programmatically (e.g., every Wednesday at 12:00 PM). Don’t worry if you don’t fully understand Crontab, there is a small help section on the same page that guides its use, and if not, you can use Crontab Guru. Additionally, you can configure execution times and reports, but my recommendation is to leave it as is by default unless you need something specific.

 

 

Creating a new cron task. What’s interesting about Ultimate Cron is the ability to configure custom tasks since generally, tasks from other contributed modules tend to be quite uniform. If the task, like those from contributed modules, is also quick and painless for the system, the best and fastest implementation is a hook_cron() in a custom module with the code you want to execute in the cron task:

/**
 * Implements hook_cron().
 */
function example_cron() {
  \Drupal::logger("example")->notice("Hey there, I’m using WhatsApp, I mean, Drupal.");
}

And now, for Ultimate Cron to detect the new cron task, you need to discover it using the “Discover Tasks” button at /admin/config/system/cron/jobs. And congratulations, you’ve created your first configurable Drupal cron task. Remember that, as with all configurations in Drupal, you must export it to consolidate it.

 

 

 

Problems, problems, and more problems. Implementing a cron task in a hook is great, but what if you want to create more than one cron task per module? Surely someone has created many custom modules just for this purpose. We don’t judge anyone here, but there’s a better solution: install cron configurations. For this, the easiest approach is to use the YML configuration file of another cron as a template, for example, the configuration file of the example task created earlier (ultimate_cron.job.example_cron.yml):

uuid: 95f9d95c-3fb0-4a36-a20f-223b496272za
langcode: en
status: true
dependencies:
  module:
    - example
title: 'Default cron handler'
id: example_cron
weight: 0
module: example
callback: example_cron
scheduler:
  id: simple
launcher:
  id: serial
logger:
  id: database

Starting from the content of this file, copy its contents to your custom module inside config/cron/ultimate_cron.job.example_cron_two.yml and remove the uuid line (the first line), langcode, and weight, as these will be configured by the system. Also, change the id to some identifier representing the cron task, for example example_cron_two, and the title to something similar to the identifier, such as “Example cron 2” (Extremely descriptive, I know). Now, importantly, callback will be the response function of the cron task where its logic will be implemented. It’s best to give it a name that does not interfere with other functions, such as “_example_two_cron_job_”, and module is the module where the response function will be implemented (so it can be called primarily, acting as a dependency). After these adjustments, the file config/cron/ultimate_cron.job.example_cron_two.yml should look like this:

status: true
dependencies:
  module:
    - example
title: 'Example cron 2'
id: example_cron_two
module: example
callback: _example_two_cron_job_
scheduler:
  id: simple
launcher:
  id: serial
logger:
  id: database

And you should define the response function within the custom module:

/**
 * Execute example_cron_two cron task.
 */
function _example_two_cron_job_() {
  \Drupal::logger("example")->notice("Hey there, I’m using WhatsApp, I mean, Drupal (Again)");
}

This process can be repeated as many times as needed for cron tasks in a module, and finally, import all configurations with the command:

drush config-import --source=modules/custom/example/config/cron --partial -y

Configure them for scheduling, and export the configuration to consolidate it along with the rest of the settings.

 

 

Conclusion. Properly managing cron tasks in Drupal is essential for optimizing system performance and ensuring that necessary processes run at the right time. The contributed module Ultimate Cron proves to be an effective solution, allowing detailed and customized configuration of each scheduled task. This not only prevents server overload but also ensures that each task runs with the ideal frequency. With Ultimate Cron, managing cron tasks in Drupal becomes a controlled and efficient process, enhancing both server performance and site functionality.
