Actualización selectiva de entidades durante migraciones de Drupal

Drupal
Migrate

Atleta saltando vallas

Pablo Urrea

Lectura de 5 minutos
Publicado
25/08/2024

Algunas veces las migraciones de Drupal deben actualizar entidades en lugar de crearlos con el parámetro de migración --update, durante este proceso se actualizarán todos las entidades de la migración previa, junto a la creación de posibles entidades nuevas. Para bien o para mal, los datos nuevos actualizarán todas las entidades disponibles en el sistema y la fuente de datos, pero, ¿Y si fuese necesaria una actualización de datos pero solo de algunas entidades?

 

El método unitario. Si requieres actualizar únicamente algunas entidades, pero no demasiadas, puedes agregar al comando de migración el parámetro --idlist seguido de los identificadores de migración correspondiente a cada grupo de datos, es decir, si por ejemplo tienes los siguientes datos en formato JSON:

{
  "elements": [
    {
      "element": {
        "id": "1",
        "name": "Nombre 1"
      },
      "element": {
        "id": "2",
        "name": "Nombre 2"
      },
      "element": {
        "id": "3",
        "name": "Nombre 3"
      },
      "element": {
        "id": "4",
        "name": "Nombre 4"
      },
    }
  ]
}

Teniendo estos datos inyectados en una migración, si solamente necesitas migrar los elementos con id's 1, 2, y 3, el parámetro sería --idlist=1,2,3. Aplicado a un comando de migración completo con drush quedaría así:

drush migrate-import migrate_elements --idlist=1,2,3

Si en lugar de crearlos, necesitas actualizarlos, el comando quedaría así con el parámetro --update:

drush migrate-import migrate_elements --update --idlist=1,2,3

Esta forma de migrar entidades individualmente es muy sencillo y rápido, pero solamente es aplicable a un volumen reducido de identificadores (A menos que tengas ganas de introducir 1000 id’s en el parámetro del comando, que igual una IA generativa lo procesa bien, pero habría que ver como lo soporta el sistema)

 

 

El método colectivo. Tras proponer el siguiente caso: “El editor necesita que realices la migración de muchas, muchísimas, demasiadas entidades, una barbaridad de entidades. Y este editor comprobará individualmente que todas las entidades se han migrado correctamente y quisiera “bloquear” de alguna forma las entidades que se hayan migrado correctamente y actualizar en la fuente los datos de entidades que no se hayan migrado bien.” Y te planteas tú, si hay alguna forma de actualizar todas las entidades salvo las bloqueadas. Pues bien, lo primero sería crear un campo booleano (TRUE o FALSE) que decida si una entidad está bloqueada o no, y ahora, el siguiente plugin custom de Migrate comprobará en la base de datos si ya se ha migrado la entidad de la Row actual, y el valor proporcionado para el campo proporcionado en los parámetros field y value del plugin:

/**
 * Migrate plugin that returns NULL if it finds the field next to the provided value or TRUE.
 * These return variables facilitate further processing such as skipping the row, for example.
 * It does not need a source and generates its own return value.
 *
 * @MigrateProcessPlugin(
 *   id = "check_entity_field_value"
 * )
 *
 * Example usage:
 * @code
 * check_entity_field_value_example:
 *   plugin: check_entity_field_value
 *   field: field_to_check
 *   value: value_to_check
 * @endcode
 */
class CheckEntityFieldValue extends ProcessPluginBase implements ContainerFactoryPluginInterface {

  /**
   * The migration.
   *
   * @var \Drupal\migrate\Plugin\MigrationInterface|null
   */
  protected $migration;

  /**
   * The entity type manager.
   *
   * @var \Drupal\Core\Entity\EntityTypeManagerInterface
   */
  protected $entity_type_manager;

  /**
   * {@inheritdoc}
   */
  public static function create(ContainerInterface $container, array $configuration, $plugin_id, $plugin_definition, MigrationInterface $migration = NULL) {
    $instance = new static($configuration, $plugin_id, $plugin_definition);
    $instance->entity_type_manager = $container->get('entity_type.manager');
    $instance->migration = $migration;

    return $instance;
  }

  /**
   * {@inheritdoc}
   */
  public function transform($value, MigrateExecutableInterface $migrate_executable, Row $row, $destination_property): bool|null {
    /** @var \Drupal\Core\Entity\EntityTypeInterface|string $entity_type */
    $entity_type = $this->getMigrationTargetEntityType($this->migration);
    $field = (isset($this->configuration['field']) && is_string($this->configuration['field'])) ? $this->configuration['field'] : NULL;
    if (isset($entity_type) && isset($field)) {
      $destination_ids = $this->getEntityIdsFromRow($row);
 
      if (!empty($destination_ids)) {
        $value = (isset($this->configuration['value'])) ? $this->configuration['value'] : NULL;
        foreach ($destination_ids as $entity_id) {
          if (!$entity_id) {
            continue;
          }

          /** @var \Drupal\Core\Entity\EntityInterface|null $entity */
          $entity = $this->entity_type_manager->getStorage($entity_type)->load($entity_id);
          if ($entity instanceof FieldableEntityInterface && $entity->hasField($field)) {
            // Returns NULL if it finds the field with any value
            // if the value is not specified, or if it is equal
            // to the value if the value has been specified.
            if ((isset($this->configuration['value']) && ((isset($entity->$field->value) && $entity->$field->value == $this->configuration['value']) || (isset($entity->$field->target_id) && $entity->$field->target_id == $this->configuration['value']))) || (!isset($this->configuration['value']) && (isset($entity->$field->value) || isset($entity->$field->target_id)))) {
              return NULL;
            }
          }
        }
      }
    }

    return TRUE;
  }

  /**
   * Retrieves the target entity type for a given migration.
   *
   * @param \Drupal\migrate\Plugin\MigrationInterface $migration
   *   The migration object from which to retrieve the target entity type.
   *
   * @return string|null
   *   The target entity type if it can be determined.
   *
   * @throws \Exception $e
   */
  protected function getMigrationTargetEntityType(MigrationInterface $migration): string|null {
    try {
      /** @var \Drupal\migrate\Plugin\MigrateDestinationInterface $migration_destination_plugin */
      $migration_destination_plugin = $migration->getDestinationPlugin();
      /** @var \Drupal\Component\Plugin\Definition\PluginDefinitionInterface|array $migration_destination_plugin_definition */
      $migration_destination_plugin_definition = $migration_destination_plugin->getPluginDefinition();

      // Gets from the plugin definition the id of the target entity,
      // it will always be the first match or none.
      preg_match('/:([^:]+)$/', $migration_destination_plugin_definition['id'], $entity_type);

      return (isset($entity_type[1]) && is_string($entity_type[1])) ? $entity_type[1] : NULL;
    }
    catch (\Exception $e) {
      return NULL;
    }
  }

  /**
   * Retrieves destination entity IDs from a migration row.
   *
   * @param \Drupal\migrate\Row $row
   *   The migration row object from which to retrieve the entity IDs.
   *
   * @return array
   *   An associative array of destination ID values.
   */
  protected function getEntityIdsFromRow(Row $row): array {
    $destination_ids = [];

    $mid_map = $row->getIdMap();
    if (!empty($mid_map)) {
      foreach ($mid_map as $mid_map_element => $mid_map_element_value) {
        // Destination IDs are always added with the same ID
        // and a counter (destid1, destid2, destid3, etc.).
        if (str_contains($mid_map_element, 'destid')) {
          $destination_ids[$mid_map_element] = $mid_map_element_value;
        }
      }
    }

    return $destination_ids;
  }
}

Este plugin, por cada Row, primero obtiene el parámetro del campo y el tipo de entidad a comprobar mediante el método getMigrationTargetEntityType() con la migración actual del dato de destino con una expresión regular. Posteriormente, obtiene, si existe, la entidad destino con el método getEntityIdsFromRow() que necesitará la fila actual para obtener datos en crudo de la base de datos, este resultado solo contendrá valores de ser una actualización de migración. Una vez obtenidos estos datos, se puede cargar la entidad destino y comprobar si el campo, de tenerlo, tiene el valor especificado.

 

Ahora habría que añadir el plugin según el ejemplo a la migración, por ejemplo, si necesitamos que ignore la entidad cuando el campo booleano field_migrate_skip contenga el valor TRUE, el plugín se definirá de la siguiente forma:

skip_row_on_field_migrate_skip_true:
  -
    plugin: check_entity_field_value
    field: field_migrate_skip
    value: TRUE
  -
    plugin: skip_on_empty
    method: row
    message: 'Ignored because field field_migrate_skip is TRUE.'

Esto saltará la Row de la migración si el valor del campo field_migrate_skip es igual a TRUE, porque el plugin retornará NULL y el plugin skip_on_empty lo identificará como un valor vacío, de lo contrario recibirá TRUE y no saltará la Row, dejando intactas las entidades “bloqueadas” por el editor.

Aunque este sea un caso ficticio, tiene multitud de aplicaciones, como por ejemplo una actualización masiva de entidades proporcionando un valor al campo si se cumplen una serie de condiciones.

 

 

Conclusión. Tanto si necesitas actualizar pocas entidades durante una migración, como si necesitas saltar unas pocas, existen distintos métodos para realizar esta actualización de datos. Solamente es necesario que tengas en cuenta que método es más conveniente para la necesidad de la migración.
