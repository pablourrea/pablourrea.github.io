Ultimate Cron para dominar todas las tareas automáticas en Drupal

Drupal
Cron

Representación del gestor de tareas del cron de Drupal como “La persistencia de la memoria” de Salvador Dalí

Pablo Urrea

Lectura de 12 minutos
Publicado
27/08/2024

El núcleo de Drupal incluye su propio cron integrado que permite programar tareas automáticas, lo que da la posibilidad de añadir tareas personalizadas que se ejecutarán cuando se active el cron en Drupal. El problema es que Drupal ejecuta todas las tareas durante la ejecución del cron, lo que puede ser un inconveniente si necesitas que una de ellas se ejecute con mayor o menor frecuencia.

Esto tiene el inconveniente de decidir si ejecutar las tareas del cron menos frecuentemente, pero con un impacto menor sobre el servidor y dejando atrás tareas que requieren realizarse con mayor frecuencia; o si, por el contrario, se ejecutarán las tareas más frecuentemente, sobrecargando así el servidor con tareas menos necesarias.

También es posible que una tarea diaria que requiera mucho tiempo de ejecución, mayor potencia de servidor, o el ancho de banda completo de este, por lo que debería de ejecutarse es un momento de baja actividad de usuarios (Por la noche, por ejemplo, a menos que sea el servidor de un foro de programación 🌚)

 

 

El cron definitivo. Para solucionar este problema, en Drupal existe un proyecto contribuido llamado Ultimate Cron, que permite configurar y programar las tareas del cron individualmente, para instalarlo se hace como cualquier otro módulo en Drupal con Composer ejecutando el siguiente comando en la consola:

composer require drupal/ultimate_cron

Y habilitándolo desde la sección de administración “Extender” o mediante Drush en la consola con el comando:

drush en ultimate_cron

Después de habilitarlo aparecerán todas las tareas de cron en /admin/config/system/cron/jobs o Administración > Configuración > Sistema > Cron > Cron Jobs:

 

Ahora es posible ordenar las tareas, editarlas, des-habilitarlas o ver los informes que han ido generando durante su ejecución. Al entrar en la edición de una tarea desde “Operaciones”, se podrá configurar el planificador para que sea Simple (Ejecuta la tarea cada 1 minuto, 5 minutos, 15 minutos, 30 minutos, 1 hora, 3 horas, 6 horas, 12 horas, una vez al día o una vez por semana) o para que sea de tipo Crontab, que es una forma de configurar periodos naturales de tiempo de forma programática (Por ejemplo, cada miércoles a las 12:00 pm), no te preocupes si no terminas de entender Crontab, en la misma página viene una pequeña ayuda que intuye su uso, y si no, puedes usar Crontab Guru. Además, se pueden configurar tiempos e informes de ejecución, pero mi recomendación es que a menos que sea necesario para algo específico, se deje tal y como está por defecto.

 

 

Crear una nueva tarea del cron. Lo interesante de Ultimate Cron es poder configurar tareas personalizadas, ya que por lo general, las tareas de otros módulos contribuidos suelen ser bastante uniformes. Si la tarea, al igual que la de los módulos contribuidos, es también rápida e indolora para el sistema, lo mejor y más rápido de implementar es un hook_cron() en un módulo personalizado con el código que quieres ejecutar en la tarea del cron:

/**
 * Implements hook_cron().
 */
function example_cron() {
  \Drupal::logger("example")->notice("Hola, estoy usando WhatsApp, digo, Drupal.");
}

Y ahora, para que Ultimate Cron detecte la nueva tarea del cron, debes descubrirla con el botón que indica “Descubrir Tareas” en /admin/config/system/cron/jobs. Y enhorabuena, has creado tu primera tarea del cron de Drupal configurable, recuerda que como toda configuración en Drupal, debes exportarla para consolidarla.

 

 

 

Problemas, problemas y más problemas. Implementar la tarea del cron en un hook está muy bien, pero, ¿Qué sucede si se desea crear más de una tarea de cron por módulo? Seguro que alguien habrá creado muchos módulos personalizados solamente para esto, aquí no juzgamos a nadie, pero hay una solución mejor, instalar configuraciones de cron. Para ello, lo más cómodo es tomar como plantilla el archivo de configuración YML de otro cron, por ejemplo, el archivo de configuración de la tarea de ejemplo creada antes (ultimate_cron.job.example_cron.yml):

uuid: 95f9d95c-3fb0-4a36-a20f-223b496272za
langcode: en
status: true
dependencies:
  module:
    - example
title: 'Default cron handler'
id: example_cron
weight: 0
module: example
callback: example_cron
scheduler:
  id: simple
launcher:
  id: serial
logger:
  id: database

Partiendo del contenido de este archivo, se copia su contenido al módulo personalizado dentro de config/cron/ultimate_cron.job.example_cron_two.yml y se elimina la línea de uuid (La primera línea), langcode y weight, ya que esto lo configurará el sistema. También se modifica el id a algún identificador que represente la tarea del cron, por ejemplo example_cron_two y el title a algo similar al identificador, por ejemplo “Example cron 2” (Extremadamente representativo, lo sé). Ahora lo importante, callback será la función de respuesta de la tarea del cron, dónde se implementará su lógica, lo mejor es darle un nombre que no interfiera con otras funciones, como por ejemplo “_example_two_cron_job_”, module es el módulo donde se implementará la función de respuesta (Para que pueda llamarlo principalmente, actúa como dependencia). Tras estos ajustes, el archivo config/cron/ultimate_cron.job.example_cron_two.yml debe de quedar así:

status: true
dependencies:
  module:
    - example
title: 'Example cron 2'
id: example_cron_two
module: example
callback: _example_two_cron_job_
scheduler:
  id: simple
launcher:
  id: serial
logger:
  id: database

Y se debe definir la función de respuesta dentro del módulo personalizado:

/**
 * Execute example_cron_two cron task.
 */
function _example_two_cron_job_() {
  \Drupal::logger("example")->notice("Hola, estoy usando WhatsApp, digo, Drupal (De nuevo)");
}

Este proceso se puede repetir tantas veces como tareas de cron se necesiten para un módulo, y finalmente, se importan todas las configuraciones con el comando:

drush config-import --source=modules/custom/example/config/cron --partial -y

Se configuran para planificarlas, y se exporta la configuración para consolidarlas junto al resto de configuraciones.

 

 

Conclusión. Gestionar adecuadamente las tareas cron en Drupal es fundamental para optimizar el rendimiento del sistema y asegurar que los procesos necesarios se ejecuten en el momento oportuno. El módulo contribuido Ultimate Cron se presenta como una solución efectiva, permitiendo una configuración detallada y personalizada de cada tarea programada. Esto no solo previene la sobrecarga del servidor, sino que también garantiza que cada tarea se ejecute con la frecuencia ideal. Con Ultimate Cron, administrar las tareas cron en Drupal se convierte en un proceso controlado y eficiente, mejorando tanto el rendimiento del servidor como la funcionalidad del sitio.
