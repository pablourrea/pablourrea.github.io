Prism Como Servidor API proxy de validación

NodeJS
API
Proxy

Red - Pixabay

Pablo Urrea

Lectura de 5 minutos
Publicado
25/05/2024

Utilizar Prism como proxy para APIs REST, una herramienta que no solo valida las peticiones según las definiciones de OpenAPI, sino que también facilita la redirección de estas a un puerto único, mejorando así el flujo de trabajo y la robustez de las aplicaciones.

En el artículo Prism Como Servidor API REST De Pruebas ya profundizo sobre la instalación y configuración básica de Prism, por lo que en este artículo voy a saltar el proceso de instalación y validación que utiliza Prism con las definiciones de OpenAPI.

 

Utilizar Prism como proxy de API REST tiene como principal ventaja la validación de las peticiones contra el puerto, pero también hay que tener en cuenta que esta funcionalidad redirige todas las peticiones a un único puerto API REST, esto supone un desafío si tienes más de un puerto en tu funcionalidad. Este concepto es más sencillo de entender con los siguientes esquemas:

 

 

 

 

Pescar peticiones con la red de Prism. Teniendo esto claro, levantar el proxy es tan sencillo como ejecutar el siguiente comando:

prism proxy openapi.yaml https://www.example.com/api/v1/port/

 

Aunque Prism permite configurar algunos ajustes del proxy mediante parámetros, a continuación te muestro los más útiles:
--errors: Parámetro recomendado. La respuesta a la petición genera un error si no se valida con las definiciones. Por ejemplo:

prism proxy openapi.yaml https://www.example.com/api/v1/port/ --errors

-h: Modifica la dirección IP a la proporcionada. Por ejemplo:

prism proxy -h 0.0.0.0 openapi.yaml https://www.example.com/api/v1/port/

-p: Modifica el puerto de red al proporcionado. Por ejemplo:

prism proxy -p 9999 openapi.yaml https://www.example.com/api/v1/port/

-m: Habilita el multiproceso. Parámetro recomendado si el proxy va a recibir muchas peticiones. Por ejemplo:

prism proxy -m openapi.yaml https://www.example.com/api/v1/port/

 

Una vez iniciado el servidor, ya se pueden realizar solicitudes al servicio desde tu máquina a la IP local (O a la IP de la máquina remota si se instala en un servidor remoto):

curl http://localhost:4010/users

Prism acepta configuraciones de métodos GET, POST, PUT, PATCH y DELETE.

 

 

¿Y en el puerto API REST real qué sucede? Depurando la solicitud en el puerto API REST real, se puede comprobar que el proxy ha realizado la petición contra el puerto, enviando mediante el parámetro “q” de query la URL del puerto sobre el cual se desea interactuar. Por ejemplo, si tienes un puerto API REST /users/delete que realiza una acción con el método DELETE sobre un ID de usuario en el cuerpo {id: 1}, al realizar la petición se realiza contra el proxy de Prism, este valida la petición y la transfiere al puerto API REST real /api/v1/port la petición como /api/v1/port?q=/users/delete con el método DELETE y el cuerpo de la petición {id: 1}, el cual devuelve un código de estado y un mensaje en el cuerpo que se transfiere al proxy, y este devuelve al cliente:

 

 

 

Conclusión. Prism se presenta como una herramienta valiosa para validar y redirigir peticiones API REST, funcionando como un proxy eficaz que asegura que las solicitudes cumplan con las definiciones de OpenAPI antes de ser procesadas por el puerto API REST real. Esto no solo simplifica el flujo de trabajo al interceptar y validar peticiones, sino que también mejora la robustez de las aplicaciones mediante una estricta adherencia a las especificaciones del API REST, lo que se traduce en un desarrollo más seguro y eficiente.


 

Si necesitas más información acerca del paquete, puedes consultar la documentación de Prism.
