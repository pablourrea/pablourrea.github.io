Migrar Paragraphs de Contenidos con Migrate (Versión mejorada)

Drupal
Migrate

¿Cómo saben las aves cómo migrar?

Pablo Urrea

Lectura de 5 minutos
Publicado
10/08/2024

En el artículo Migrar Paragraphs de Contenidos con Migrate exploro las posibilidades para migrar Paragraphs en Drupal con archivos de configuración de migración independientes al nodo padre, pero es cierto que, a pesar de ser los Paragraphs una entidad, no son una entidad principal y siempre dependen de un padre. En este artículo muestro como migrar Paragraphs y casarlos con el padre dentro de la misma migración que este, optimizando así el proceso de migración reduciendo el tiempo de ejecución, eliminando dependencias y fortaleciendo la relación padre e hijo entre las dos entidades, haciendo de este proceso un método más conveniente que el comentado en el anterior artículo.

 

Dependencias. Para utilizar este método, es necesaria la instalación del módulo para Drupal: Migrate Child Entity Generate, puedes instalarlo desde la sección “Ampliar” del administrador de Drupal o con Composer:

composer require drupal/migrate_child_entity_generate

Y habilitarlo desde la sección “Ampliar” del administrador de Drupal o con Drush:

drush en migrate_child_entity_generate

 

Un plugin de Migrate para dominarlos a todos. Utilizar el plugin child_entity_generate del módulo Migrate Child Entity Generate es muy sencillo de usar. Debes definir el plugin, el tipo de entidad, el tipo del tipo de entidad y opcionalmente definir los valores variables y variables constantes por defecto como en el siguiente ejemplo:

field_name:
  plugin: child_entity_generate
  entity_type: paragraph
  bundle: paragraph_bundle
  values:
    field_1: value_1
    field_2/value: value_2
  default_values:
    langcode: "es"
    field_2/format: "text"

La diferencia entre values y default_values es que en values se introducen valores variables para cada Paragraph distinto (Como por ejemplo, un texto, una fecha, etc.) y en default_values se introducen valores estáticos y comunes para todos los Paragraph (Como por ejemplo, el formato de un campo WYSWYG de CKEditor, un campo de selección de idioma, etc.).

 

Un plugin de Migrate para dominar todos los valores. A diferencia del plugin entity_generate del módulo Migrate Plus, el plugin child_entity_generate sí que acepta como parámetro un array de valores, como por ejemplo:

destination:
 plugin: "entity:node"
source:
 fields:
   -
     faq_items:
       -
         question: "Some question"
         answer: "Some answer"
       -
         question: "Another question"
         answer: "Another answer"
process:
 field_faqs:
   plugin: child_entity_generate
   source: faq_items
   entity_type: field_collection
   bundle: faq
   values:
     field_faq_question: question
     field_faq_answer/value: answer
   default_values:
     field_faq_answer/format: "basic_html"

El código anterior crearía una entidad faq_items del tipo faq por cada elemento del array faq_items, asignando al campo field_faq_question el valor de question y el valor de answer al valor del campo field_faq_answer, dejando el formato del campo field_faq_answer basic_html como valor por defecto general a todas las entidades. Y asignaría el target_id y el target_revision_id de cada entidad al campo field_faqs.

 

ℹ️
En el momento de publicación de este artículo, el módulo Migrate Child Entity Generate en la versión estable 1.0.1 del 4 de junio del 2024 no acepta referencias de campos de la Row actual del proceso de migración (Como por ejemplo asignar a field el valor de "@other_field"). Para corregirlo he creado un parche que el mantenedor del modulo aceptó en la issue "Refine the process value filtering so that it gets values from the row". Si lo necesitas puedes aplicar el siguiente parche o instalar la versión de desarrollo 1.x-dev del módulo.

 

Conclusión. Migrar Paragraphs en Drupal de manera eficiente es un desafío, pero el uso del módulo Migrate Child Entity Generate presenta una solución poderosa. A través de este método, es posible integrar los Paragraphs directamente con sus nodos padres en una sola migración. Además, el plugin child_entity_generate ofrece un método robusto y eficaz para la migración de Paragraphs en Drupal.
