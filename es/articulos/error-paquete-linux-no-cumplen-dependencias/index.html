Error en el paquete: No se cumplen las dependencias

Pablo Urrea

Lectura de 5 minutos
Publicado
14/02/2025

Al tratar de instalar o actualizar una aplicación o programa en Linux, este proceso hay que realizarlo mediante un paquete .deb si tienes un sistema Debian, Ubuntu, etc. o mediante un paquete .rpm para sistemas Red Hat, Fedora, etc. ya sea por preferencias o por decisión de los desarrolladores. Normalmente, esta instalación no suele dar dolor de cabeza, simplemente sigues los pasos del instalador y ya está listo para usar el programa, pero, a veces, este muestra en el primer paso el error “Error en el paquete: No se cumplen las dependencias”.

 

 

¿Qué significa este error? Para poder solucionarlo no es necesario pero si recomendable comprender el origen del error, y es que este se debe a que el paquete que se está tratando de instalar requiere ciertas dependencias que no están disponibles, no son compatibles o entran en conflicto con otras versiones ya instaladas en el sistema. Algunas posibles causas concretas pueden ser que el paquete necesita otros paquetes que no están instalados; o que las dependencias requeridas tienen versiones específicas, pero el sistema tiene versiones diferentes instaladas; o si el paquete proviene de una fuente externa, podría haber incompatibilidades con los paquetes en los repositorios oficiales de tu distribución; o quizás la versión del paquete puede no ser compatible con la versión de tu sistema operativo; incluso es posible que si estás instalando un paquete manualmente sin resolver dependencias, el sistema no puede instalarlo correctamente. En cualquier caso este error tiene varias soluciones posibles, para ellas tomaré de ejemplo el paquete de VSC o Visual Studio Code.

 

Solución 1: Forzar la instalación del paquete con dpkg. Mediante consola es posible forzar la instalación del paquete de forma rápida con permisos de administrador, para ello hay que ejecutar el comando dpkg como superusuario, el parámetro -i y la ruta al archivo de instalación (Lo más cómodo es hacerlo desde la propia en la que se encuentra el archivo). Quedando algo como esto:

sudo dpkg -i archivo.deb

 

 

Solución 2: Tratar de arreglar las dependencias. Existe la posibilidad de agregar las dependencias mediante apt en consola como usuario administrador. Para ello hay que ejecutar

sudo apt --fix-broken install
sudo apt install -f

Y posteriormente reinstalar el paquete.

 

Solución 3: Combinar las soluciones 1 (Forzar la instalación) y 2 (Arreglar las dependencias). Si el error persiste a lo largo de las nuevas actualizaciones lo mejor es forzar la instalación y posteriormente instalar las dependencias del sistema. Para ello primero es necesario ejecutar el comando dpkg como superusuario, el parámetro -i y la ruta al archivo de instalación (Lo más cómodo es hacerlo desde la propia en la que se encuentra el archivo). Quedando algo como esto:

sudo dpkg -i archivo.deb

 

Y posteriormente agregar las dependencias mediante apt con el siguiente comando:

sudo apt --fix-broken install

 

Solución 4: Revisar el motivo específico. Existe la posibilidad de mirar el motivo concreto del error, aunque esta solución es más tediosa y lenta, ya que hay que revisar cada motivo específico, para ello hay que ejecutar el comando como usuario administrador:

sudo apt show code

O comprobar directamente el archivo de informes:

cat /var/log/apt/term.log
